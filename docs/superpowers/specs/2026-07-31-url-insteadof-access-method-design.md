# Design: URL insteadOf by profile access method

Date: 2026-07-31

## Problem

Folder rules correctly set `user.*` and `core.sshCommand`, but HTTPS remotes still authenticate via global Git Credential Manager. Users expect assigning an SSH profile to a folder to make `git push` use that profile’s SSH key without manually changing remotes.

## Decision

Use Git `url.<base>.insteadOf` inside generated profile config (option 1 from brainstorming).

- SSH profile: rewrite `https://HOST/` and `ssh://git@HOST/` → `git@HOST:`
- HTTPS profile: rewrite `git@HOST:` and `ssh://git@HOST/` → `https://HOST/`
- Apply for each entry in `profile.hosts`
- Generated by `GitConfigGenerator.profileConfig`; applied through existing `ManagedGitConfigInstaller` / `includeIf` folder rules
- Do not mutate `.git/config` remotes
- Do not switch GCM/Keychain tokens

## Edge case

When global active profile and folder profile use different access methods, `insteadOf` entries can accumulate. `doctor` should warn when that mismatch is detected for the inspected path.

## Out of scope

- Remote URL mutation (`git remote set-url`)
- Per-folder HTTPS credential switching
- Host alias blocks (`github.com-work`) beyond insteadOf
